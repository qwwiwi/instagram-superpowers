# Воронка после quick_setup: гейт → оффер → отложенная карточка

`automations_quick_setup` создаёт гейт и оффер. Этот файл – как достроить воронку до рабочей схемы: вторая кнопка в оффере и отложенное сообщение с карточкой. Если вам достаточно «слово → DM с одной ссылкой», этот файл можно пропустить.

Перед сборкой прочитайте гочу «Template против QuickAnswer» в [SKILL.md](../SKILL.md): все видимые сообщения – только `formType: "template"`.

## Модель потока

Воронка – это `steps[].messages[]`. У каждого блока:

- `actionType`: `message` (видимое сообщение) или `action` (служебный узел).
- `formType` (для `message`): `template` (карточка, кнопки внутри пузыря) или `quickAnswer` (простой текст, кнопка сбоку чипом – не используем).
- `nextStepId` – АВТО-стрелка: выполняется сама после блока.
- `inlineButtons[]` – кнопки; у каждой свой `subtype` и (для callback) свой `nextMessageId` – стрелка ПО КЛИКУ.

### Два вида стрелок

| Инструмент | Что ставит | Семантика |
|---|---|---|
| `automations_messages_connect(triggerMessageId, sendMessageId)` | `nextStepId` | авто-переход блок → блок |
| `automations_buttons_connect(buttonId, nextMessageId)` | `nextMessageId` кнопки | переход по клику |

- `messages_connect` без `sendMessageId` существующую авто-стрелку НЕ убирает (ограничение API). Чтобы убрать авто-переход, удалите узел и создайте заново.
- `buttons_connect` без `nextMessageId` отвязывает навигацию кнопки: сама кнопка остаётся.

### Кнопки: url против callback

- `subtype: "url"` – открывает ссылку и НЕ ведёт по воронке. Для переходов наружу: гайд, бот, канал.
- callback (`subtype: 1`) – ведёт к `nextMessageId`. Для гейта «Забрать» → оффер.

### Action-блоки не показывают сообщение

`actionType: "action"` выполняет только subActions (тег, задержка и т. п.) и ничего не рисует. Любой текст или кнопка, которые должен увидеть человек, – только в `actionType: "message"`. Кнопку на action-блок повесить нельзя: API примет, `automations_get_detail` покажет, а человек не увидит ничего.

### Отложенное сообщение

Задержка – action-узел с субдействием:

```json
{"actionLabel":"delay","tags":[],"fields":{"type":3,"delay":"1","chosenDays":[]}}
```

`type`: 1 – секунды, 2 – минуты, 3 – часы, 4 – дни. `delay` – число строкой. Ставится через `automations_actions_setup(messageId, subActions=[...])`. Цепочка: `оффер --авто--> [delay] --авто--> [сообщение-карточка]`. Если в quick_setup переданы `additionalMaterial*`, этот узел создаётся сам; в остальных случаях – вручную.

## Откуда берутся дубли отправок

Если к узлу-отправке (или к узлу, который авто-цепочкой ведёт в отправку) идёт НЕСКОЛЬКО стрелок – авто `nextStepId` плюс клики по кнопкам, – то каждый проход даёт ещё одну отправку. Пример: оффер → карточка по авто, и ещё две кнопки оффера ведут туда же – карточка канала уходит 3–4 раза.

**Правило:** к цепочке delay → отправка ведёт РОВНО один путь. Кнопки оффера делайте `subtype: "url"` (они не ведут по воронке), тогда по воронке идёт только кнопка гейта.

## Эталонная схема

```
гейт (message / template, БЕЗ ссылки): текст + «Забрать» (callback) --клик--> оффер
оффер (message / template): текст
    + «Открыть гайд»   (subtype: url -> https://yourdomain.com/guide)   [не ведёт по воронке]
    + «Хочу систему»   (subtype: url -> https://yourdomain.com/system)  [не ведёт по воронке]
оффер --авто (nextStepId)--> [delay 1 час] --авто--> карточка
    (message / template: кнопка «Перейти в канал» -> https://t.me/+YOUR_CHANNEL_INVITE)
```

- Гейт без ссылки безопаснее для Instagram: ссылка приходит только во втором сообщении, после клика.
- Вторая кнопка («Хочу систему») ведёт ссылкой сразу на нужное место, без промежуточного сообщения.
- Карточка канала с `YOUR_CHANNEL_INVITE` нужна только если у вас есть Telegram-канал. Если нет – воронка кончается оффером, delay-узел не нужен.

## Порядок сборки

1. `automations_quick_setup` (см. [keyword-workflow.md](keyword-workflow.md), шаг 3) – готовые гейт и оффер.
2. `automations_get_detail` – запишите id сообщений и кнопок.
3. Вторая url-кнопка в оффере (`inline_buttons_setup` с `subtype: "url"`).
4. Если `additionalMaterial*` уже переданы в quick_setup, найдите созданные delay-узел и сообщение через `automations_get_detail` и доработайте их. Иначе, если нужна карточка, создайте сообщение с `formType: "template"` и один delay-узел между оффером и карточкой. Не создавайте вторую отложенную цепочку.
5. Снимите `<p>`-обёртки с текстов (quick_setup их добавляет).
6. Проверка по поведению: `automations_get_detail` + живой тест.

## Чеклист сборки

- [ ] Видимые сообщения – `actionType: "message"`, не `action`
- [ ] Всё, где есть кнопка со ссылкой, – `formType: "template"`
- [ ] Навигирует только кнопка гейта, остальные кнопки `subtype: "url"`
- [ ] Если карточка нужна: delay-узел один на пути к карточке (без карточки пункт пропустите)
- [ ] Статус воронки Active
- [ ] Живой тест ОДНОЙ воронки в реальном директе до тиражирования: структурная проверка «кнопка есть» не ловит дубли и невидимые сообщения

## Полезное

- `automations_delete(automationId)` есть: воронку можно удалить начисто и собрать заново.
- Починить воронку сменой `actionType` узла нельзя – узел пересоздают (delete + create).
- Много вызовов подряд на одну воронку (больше ~6) могут давать 500: делайте паузы и повторы, структуру и отложенную часть собирайте отдельными проходами.
