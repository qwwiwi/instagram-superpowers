# Монтаж рилса на ffmpeg и Groq

Берёт сырой дубль одного говорящего человека и делает из него готовый рилс: убирает
паузы, повторы и ложные старты, склеивает, выравнивает громкость, вшивает субтитры
(этап 1); по желанию монтирует его по регламенту – сплит, графика, субтитры по месту,
призыв – и принимает по кадрам (этап 2). Всё считается локально; наружу уходит только
звук дубля в Groq, если выбран движок `groq` (с движком `local` не уходит ничего).

В отличие от монтажа через приложение Edits, здесь не нужен ни Edits, ни его
автоматизация: достаточно ffmpeg, Python и ключа Groq.

**Скилл сам не публикует.** Результат – файл `reel-captioned.mp4` (этап 1) или `reel.mp4`
(этап 2). Выкладывает его человек; агент – только по явному слову человека для этого файла
и только кликами в приложении, см. «Шаг 4. Публикация».

## Общий порядок: четыре шага

1. **Нарезка** – этап 1, шаги 1–6 ниже: транскрипт, таблица фраз, план, рендер,
   проверка `verify.py`. Результат – `reel-cut.mp4` и `words-cut.json`.
2. **Субтитры и анимация** – шаг 7 этапа 1 (только субтитры) или этап 2 (монтаж по
   регламенту: сплит, вставки, субтитры по месту, призыв).
3. **Приёмка** – свежим приёмщиком, который ролик не собирал: `verify.py`, кадры и листы,
   чек-лист `references/montage-acceptance.md` (этап 2) или кадры стыков и субтитров
   (этап 1). Самоприёмка сборщика не считается.
4. **Публикация** – раздел «Шаг 4. Публикация»: по умолчанию человек выкладывает файл
   сам; агент – только по явному слову для этого файла.

## Модель

Все шаги монтажа – разбор референсов, раскадровка, сборка, приёмка и все субагенты этих
шагов – идут на самой сильной модели с рассуждением на среднем уровне (сейчас это Claude
Opus 5.5, уровень medium). Облегчённые модели (класса Sonnet) для монтажа не используются:
на них падает внимание к мелочам и к раскладке кадра – заготовки, пустые полосы, текст
поверх текста и срезанный подбородок проходят незамеченными.

## Что нужно до начала

Агент проверяет это первым шагом и говорит студенту, чего не хватает.

| Что | Как проверить | Если нет |
|---|---|---|
| ffmpeg и ffprobe | `ffmpeg -version`, `ffprobe -version` | поставить ffmpeg |
| Субтитры: libass **или** Pillow | `ffmpeg -hide_banner -filters \| grep -E ' (ass\|subtitles) '` – есть строка: libass есть, ничего ставить не нужно. Нет строки (так у стандартной формулы Homebrew `ffmpeg`): нужен Pillow, `python3 -c "import PIL"` | ставить Pillow, см. ниже. Пересобирать ffmpeg не нужно |
| Python 3.10+ | `python3 --version` | поставить Python |
| Распознавание: ключ Groq или локальный Whisper | ключ: переменная `GROQ_API_KEY` задана, либо есть файл `~/.secrets/groq/env`. Локальный Whisper: `python3 -c "import faster_whisper"` (или `.venv/bin/python -c ...`) проходит без ошибки | нужен один из двух. Groq: завести аккаунт, ключ создаётся в консоли Groq, показывается при создании – сохраните сразу. Локально: поставить `faster-whisper`, см. шаг 1 |

Ключ кладите в окружение или в файл `~/.secrets/groq/env` (права `chmod 600`):

```bash
mkdir -p ~/.secrets/groq
cat > ~/.secrets/groq/env <<'EOF'
export GROQ_API_KEY="<ВАШ_КЛЮЧ>"
EOF
chmod 600 ~/.secrets/groq/env
```

Скрипты берут ключ из переменной `GROQ_API_KEY`, а если её нет – из этого файла. Ключ
не печатается, не пишется в логи и не попадает в выходные файлы. Не вставляйте его в
команды, в чат и в репозиторий.

Субтитры вшиваются одним из двух способов (подробно в шаге 7). Первый требует ffmpeg с
libass, второй – только фильтр `overlay`, который есть в любой сборке, и пакет Pillow.
Скрипт выбирает сам: есть libass – первый, нет – второй. Стандартная формула Homebrew
`ffmpeg` libass не содержит, поэтому на обычном Mac пригодится Pillow:

```bash
python3 -m pip install pillow
```

Если pip отвечает `externally-managed-environment` (так у Python из Homebrew), заведите
виртуальное окружение и запускайте скрипты его Python:

```bash
python3 -m venv .venv && .venv/bin/python -m pip install pillow
```

Pillow нужен только для субтитров через PNG; остальные шаги работают без него.

Дубль: вертикальное видео 9:16 с одним говорящим и звуком. Скрипты лежат в
`scripts/` этого скилла. Ниже `S` – путь к ним:

```bash
S=~/.claude/skills/reels-ffmpeg-montage/scripts
mkdir -p reel-work && cd reel-work     # рабочая папка: сюда лягут все файлы
```

## Роли

Скрипты считают **факты**: слова, паузы, сходство фраз, громкость. **Решает агент**,
какие фразы повтор или оговорка, и **подтверждает студент**. Скрипт сам ничего не
выбрасывает по смыслу: кандидаты только помечаются, а вырезаются лишь фразы, номера
которых агент передал флагом `--drop` после «да» студента.

## Порядок работы

### 1. Транскрипт

```bash
python3 $S/transcribe.py ../take.mp4 --language ru --out words.json
```

Движок распознавания выбирает `--engine`:

- `auto` (по умолчанию) – Groq, если ключ найден; иначе локальный Whisper, если пакет
  `faster-whisper` установлен; иначе скрипт останавливается и называет оба способа.
- `groq` – быстро, нужен ключ, звук дубля уходит в Groq.
- `local` – ключ не нужен, звук не покидает компьютер, но медленнее: на процессоре заметно
  дольше. Первый запуск скачивает модель: `large-v3-turbo` (по умолчанию) – около 1,6 ГБ,
  `--model small` – около 0,5 ГБ, легче и быстрее, но точность ниже.

```bash
python3 $S/transcribe.py ../take.mp4 --engine groq --language ru --out words.json
.venv/bin/python $S/transcribe.py ../take.mp4 --engine local --language ru --out words.json
```

Локальный движок ставится в виртуальное окружение, и скрипт запускается его Python:

```bash
python3 -m venv .venv && .venv/bin/python -m pip install faster-whisper
```

Для `local` есть ещё `--device` (`cpu` по умолчанию, `cuda` для видеокарты NVIDIA),
`--compute-type` (`int8` по умолчанию) и `--model-dir` (куда класть модель; по умолчанию
кеш Hugging Face, его место задаёт `HF_HOME`).

ffmpeg достаёт моно-звук 16 кГц: для Groq – FLAC, звук уходит в Groq (`whisper-large-v3`,
слова с таймкодами); для `local` – WAV, распознаёт `faster-whisper` на этом компьютере.
Результат у обоих один и тот же – `words.json`. Язык – код ISO-639-1 (`ru`, `en`); без
`--language` язык определяется сам.

Лимит размера файла (только Groq): если FLAC больше `--max-upload-mb` (по умолчанию 25), скрипт
пересжимает звук в MP3 32 кбит/с; если и так больше – останавливается с понятным
текстом. Нарезать длинный дубль на куски он не умеет: рилс короткий.

Ошибки Groq объясняются по-человечески: 401 – ключ отклонён, 413 – файл слишком
большой, 429 – лимит запросов, подождать (скрипт покажет время ожидания, если сервис
его назвал).

### 2. Таблица фраз

```bash
python3 $S/phrases.py words.json
```

Печатает таблицу и пишет `phrases.json` и `phrases.md`: номер, начало, конец, длина,
пауза перед фразой, текст. Фраза – речь между паузами от 0,32 с; фраза короче 0,6 с
присоединяется к соседней. Фраза не заканчивается на предлог, союз или частицу («в», «и»,
«у», «что»…), если пауза после неё короче 1,5 с (`--hard-pause`; `0` – выключить) и слово не
закрывает предложение: это вдох внутри предложения, следующий кусок присоединяется.
Пауза от 1,5 с остаётся жёстким разрывом. Фразы от этого получаются длиннее, но не
обрываются посреди мысли.

**Точка решения 1. Покажи студенту таблицу целиком** (`phrases.md`) и коротко скажи,
что видишь: где повторы, где оговорки, где оборванные фразы. Прочитай текст сам:
скрипт ищет повторы по словам, а смысл оценивает агент. Пересъёмка, в которой слова
отличаются от удачного дубля (оговорка, обрыв), может не попасть в кандидаты вовсе: смотри
таблицу, а не только список кандидатов.

### 3. План нарезки, первый проход

```bash
python3 $S/plan_cut.py words.json --phrases phrases.json
```

Пишет `cut-plan.json` и `cut-plan.md`. Что делает скрипт сам: паузы от 0,4 с
сжимает до зазора 0,25 с (по 0,125 с воздуха с каждой стороны); края ролика режет по
времени слов с запасом: за 0,15 с до начала первого слова и через 0,25 с после конца
последнего (`--head-air` / `--tail-air`, в секундах ролика; с `--speed` и сеткой кадров
запас урезается так, чтобы воздух на краю не превысил 0,30 с – правило 3.7 регламента).
Внутрь слова край не заходит никогда: энергия звука двигает край только наружу – если речь
звучит раньше начала первого слова или дольше конца последнего (до 0,6 с), край уходит на
неё (`speech_edges` в плане); одно слово, которому распознаватель поставил время в тишине
рядом с голосом, забирает этот голос (если голос не дальше 1,5 с и каждый край сдвигается
наружу не больше чем на 1,5 с; звук длиннее – остаток дубля, музыка – автоматически не берётся,
остаются штампы), и план строится без ошибки. Тихие согласные внутри
штампов слова остаются всегда. Если штамп первого слова начинается сильно раньше голоса
(спикер тянется к камере), воздух на краю будет больше 0,30 с: `verify.py` это покажет –
поправь время слова в `words.json` и пересобери план. Края резов внутри ролика ставятся только туда, где звук правда
тихий (по энергии, а не по времени слов от распознавателя): если пауза не тихая,
она остаётся, если у вырезаемой фразы нет тихого края – скрипт отказывает
(`REFUSED`), и нужно предложить соседнюю фразу. В шумной комнате проверку отключает
`--no-energy`.

Охрана речи: план не пишется, если вырез задел слова фразы, которая остаётся. Считаются
только слова, а не паузы внутри фразы. Вырезы, которые скрипт предлагает сам (паузы,
начало, конец), он при необходимости сам укорачивает до границы речи, а не отказывает.
Отказ возможен только из-за `--drop`: в сообщении названы фраза, вырез и что делать (убрать
фразу из списка или добавить соседнюю).

Что скрипт только **помечает** (`candidates`): повтор (фраза почти слово в слово
повторена ближе чем через 4 фразы) и ложный старт (фраза – начало следующей, более
длинной). Чаще лучший дубль – более поздний, но решаешь ты.

**Точка решения 2. Перед рендером покажи студенту список вырезаний:**
1. кандидатов из `cut-plan.md` с твоим мнением по каждому (оставить или вырезать и
   почему);
2. итоговый список номеров фраз к вырезанию с текстом каждой;
3. итоговую длину (`output`) против исходной.

Жди явного «да». Не подтверждено – не вырезано. Любая правка списка – новый запуск
с новым `--drop`.

### 4. План нарезки, подтверждённый

```bash
python3 $S/plan_cut.py words.json --phrases phrases.json --drop 1,3 [--speed 1.3]
```

`--drop` принимает номера и диапазоны (`3,5-7`). Ускорение `--speed` (0,5–2,0) –
стилистический выбор, спроси студента; оно применяется после склейки и последним.
Не транскрибируйте уже ускоренное видео: на быстрой речи распознаватель теряет слова.

### 5. Рендер

```bash
python3 $S/render_cut.py ../take.mp4 cut-plan.json --words words.json --out reel-cut.mp4
```

Кадрово-точная нарезка и склейка с перекодированием, на каждом стыке фейд звука
несколько миллисекунд (нет щелчка), громкость около -14 LUFS в два прохода
(измерение, затем линейная коррекция), 1080x1920, 30 fps, H.264 + AAC, `faststart`.
Рядом пишутся `words-cut.json` (слова на новых временах) и `cut-map.json` (где стыки).

Если исходник не 9:16, он вписывается с чёрными полями, ничего не обрезается.
Предупреждение появится в логе: скажи студенту, что снимать надо вертикально.

### 6. Проверка

```bash
python3 $S/verify.py reel-cut.mp4 --cut-map cut-map.json --seams-dir seams
```

Проверяет: длительность не больше `--max-duration` (по умолчанию 90 с – поставьте
актуальный лимит Instagram) и совпадение с планом; 1080x1920, 30 fps, H.264 + AAC,
`faststart`; громкость около -14 LUFS и пик; нет тишины длиннее 0,8 с; воздух на краю
(«speech start», «speech end») – не больше 0,30 с на каждом краю (правило 3.7 регламента;
конец звука берётся по таймкодам аудиопакетов, поэтому разрыв внутри звука не считается
тишиной в конце, а видео, которое идёт дольше звука, – считается); первый кадр не чёрный. Код возврата 1 – есть провал: покажи студенту строки FAIL, исправь
причину и перерендери. Не обходи провал флагами.

Кадры стыков: в `seams/` для каждого стыка по картинке «до | после» (`seam-001.png`)
и `index.txt`. **Открой их и посмотри**: цифры не видят скачка позы, обрезанного
слова, лишнего кадра. Опиши студенту, что на каждом стыке. Скачок позы или голова
«прыгает» – сдвинь рез (другой `--drop` или другая фраза) и повтори с шага 4.

Необязательная проверка текста: можно запустить `transcribe.py` на `reel-cut.mp4`
(`--out words-check.json`) и сравнить с `words-cut.json` глазами. Это ещё один
запрос в Groq.

### 7. Субтитры

```bash
python3 $S/captions.py reel-cut.mp4 words-cut.json --out reel-captioned.mp4   # [--y 0.78]
```

Раскладка одна для обоих способов: 2–4 слова в строке, текущее слово подсвечено
янтарным (в каждый момент ровно одно слово), крупный жирный шрифт с толстой чёрной
обводкой и мягкой тенью (читается и на светлой стене), боковые поля 120 px, ширина
строки не больше 840 px: мимо интерфейса Instagram. Одно короткое слово («Я», «И») перед
обрезанной паузой не стоит на экране одно: оно присоединяется к следующей фразе.

**Положение.** Центр блока субтитров – на 0,78 высоты кадра (нижняя треть: ниже рта
говорящего, выше зоны интерфейса; ничто не ниже 0,82). Это одна константа
`CAPTION_CENTER_Y` в `captions.py` для обоих способов. `--y 0.80` сдвигает субтитр вниз,
`--y 0.74` вверх (допустимо 0,30–0,90). Все размеры заданы для ширины 1080 и масштабируются
от реальной ширины видео.

**Посмотри кадр.** Положение подогнано под обычный кадр говорящей головы, а у вас лицо
может быть крупнее или ниже. После вшивки достань кадр с субтитром, **открой его** и
проверь: субтитр не закрывает рот и подбородок. Если закрывает – повтори шаг с другим
`--y` (ниже, до 0,82 по низу текста; если лицо занимает почти весь низ кадра, поднимай
выше 0,78 осторожно, чтобы не залезть в зону интерфейса) и снова посмотри кадр.

`--backend auto|ass|png` (по умолчанию `auto`):

- `ass` – собирает `captions.ass` и вшивает через libass (фильтр `ass`). Нужен ffmpeg с
  libass. Шрифт – имя семейства из установленных с кириллицей: Montserrat, Inter, Arial,
  Helvetica Neue, DejaVu Sans, Liberation Sans, Noto Sans (первый найденный); свой:
  `--font "Название семейства"`, свои файлы: `--fonts-dir`.
- `png` – каждое состояние субтитров (строка с подсвеченным словом) рисуется Pillow в
  прозрачный PNG, картинки идут одним входом списка concat (на каждую свою длительность,
  в паузах пустая картинка), и один фильтр `overlay` кладёт их на видео. Нужен только
  `overlay`, который есть в любой сборке ffmpeg, и Pillow. Почему не «по одному `overlay`
  с `enable='between(t,a,b)'` на слово»: на рилсе в 150+ слов это граф из 150+ входов и
  цепочки наложений, каждое трогает каждый кадр, а команда растёт вместе со словами. Список
  лежит в файле, команда имеет постоянную длину. Размер шрифта подбирается так, чтобы
  высота текстового блока была как у стиля ASS. Шрифт – файл: берётся жирный системный с
  кириллицей (Montserrat, Inter, Arial, Tahoma, Verdana, DejaVu, Liberation, Noto
  и т. д. на macOS, Windows и Linux), свой – `--font /путь/к/шрифту.ttf`; если ничего не
  найдено, скрипт скажет об этом и попросит `--font`. `--png-dir` оставляет картинки.
- `auto` – `ass`, если у ffmpeg есть libass, иначе `png`. Если Pillow не стоит, скрипт
  печатает точную команду установки (см. «Что нужно до начала») и останавливается.

`--ass-only` только пишет `captions.ass`, ничего не вшивая: libass и Pillow не нужны.

После вшивки прогони `verify.py reel-captioned.mp4 --cut-map cut-map.json`, достань
2–3 кадра (например, `ffmpeg -ss 2 -i reel-captioned.mp4 -frames:v 1 frame.png`),
**открой и опиши**: субтитр читается, не вылезает за кадр, не закрыт интерфейсом, **не
закрывает рот и подбородок** (иначе `--y`, см. «Посмотри кадр»), подсвечено ровно одно
слово и оно совпадает с произносимым, на стыке нет одинокой буквы.

## Этап 2 – монтаж по регламенту

Этап 1 даёт чистую склейку `reel-cut.mp4` и слова `words-cut.json`. Этап 2 делает из
неё рилс по регламенту: основной кадр – сплит 50/50 (сверху графика, снизу спикер),
полноэкранные UI-макеты из слов речи, короткие «вдохи» спикера, смена кадра примерно
раз в 3 с, субтитры прописными на своём месте для каждого типа кадра, призыв с кодовым
словом в конце. Регламент выведен из покадрового разбора удачных рилсов с говорящей
головой. Своего движка сцен нет: агент собирает ролик обычными инструментами по
регламенту и скелетам.

Документы:

- `references/montage-reglament.md` – регламент: геометрия, ритм, хук, сцены, шрифты,
  цвет, субтитры, заголовки, движение, призыв, дополнительные приёмы, частые ошибки,
  детализация визуалов.
- `references/storyboard-template.md` – бланк раскадровки и пример.
- `references/layout-patterns.md` – скелеты: композиция HyperFrames (HTML + GSAP) и графы
  ffmpeg для сплита и наложений.
- `references/montage-acceptance.md` – приёмка по кадрам: чек-лист, проход «текст поверх»,
  таблица.

### Что ещё нужно

| Что | Как проверить | Если нет |
|---|---|---|
| Готовый этап 1 | есть `reel-cut.mp4` и `words-cut.json` (шаги 1–6; шаг 7 не нужен: субтитры этапа 2 свои) | пройти этап 1 |
| HyperFrames CLI (путь А) | `hyperframes --version`, `hyperframes doctor` (Chrome и ffmpeg найдены) | поставить HyperFrames CLI глобально по его документации; нужен Node.js (версию требует сам CLI – смотри `hyperframes doctor`). Без него – путь Б (только ffmpeg и заранее нарисованные сцены) |
| Pillow (по желанию) | `python3 -c "import PIL"` | без него листы приёмки без меток времени, время – из `index.txt` |
| Шрифты | файлы шрифтов трёх классов (регламент, 5.4) с кириллицей | системные того же класса, отметка в акте приёмки |

### Порядок

1. **Транскрипт.** `words-cut.json` из этапа 1.
2. **Вычитка.** Прочитай текст целиком и исправь в `words-cut.json` ошибки
   распознавателя: названия продуктов, термины, имена, числа – одной формой, той же, что
   будет на карточках (регламент, 7.7). Список правок покажи студенту.
3. **Кадр-разметка головы.**

   ```bash
   python3 $S/head_guide.py reel-cut.mp4 --time 1.0 --time 8.0 --out head-guide
   python3 $S/head_guide.py --top 610 --eyes 830 --chin 1010
   ```

   Открой `head-guide-*.png`, прочитай по линиям верх волос, глаза, подбородок и передай
   их числами: скрипт напечатает срез для сплита `y0` (регламент, 1.3), где окажутся
   волосы, глаза и подбородок, и место субтитра на плане «спикер» (7.5). Живой спикер
   двигается: возьми кадры по всему дублю (по одному на будущий план и на моменты смены
   плана, с открытым ртом и наклоном) и передай самый низкий подбородок, самые высокие глаза
   и самый высокий верх волос. Голова всегда целиком в окне спикера: верх волос не выше
   y 1000 (40 px под швом), рот и подбородок не ниже y 1520 – над нижней зоной интерфейса,
   а не под ней (регламент, 1.3). Если голова не помещается (крупный план), скрипт её не
   режет, а уменьшает спикера в сплите (масштаб 0,55–1,0, по центру) и печатает масштаб;
   боковые поля заполни размытой затемнённой копией того же кадра (`layout-patterns.md`).
   Меньше 0,55 – переснять дальше от камеры; меньше 0,85 –
   скажи студенту, что дубль снят близко. Любой срез проверяй перед сборкой:
   `head_guide.py --top T --chin C --y0 Y [--scale S]` печатает FAIL и завершается с кодом 1,
   если срез режет голову. После первого рендера сверь положение лица на кадрах готового
   ролика: `head_guide.py reel.mp4 --time …` рисует те же линии на любом видео.
   Прочитай и свойства речи: длину первого предложения (3.4) и длину призыва (10.1). Хук вне
   порога – вопрос студенту до монтажа, ответ – в шапку раскадровки. Призыв длиннее 8 с –
   вернись на этап 1 и сократи его там (`--drop`): монтаж под длинный призыв не растягивается.
   Речь должна идти с первого кадра: воздух на краю ≤ 0,30 с (правило 3.7, `verify.py`
   «speech start» / «speech end»).
4. **Раскадровка** по `references/storyboard-template.md`: шапка (голова, масштаб, кадр
   0,00 с заголовком-хуком от 72 px, длительность призыва 5–8 с), список планов с долями и
   проверкой ритма, сцены по рецептам с детализацией каждой вставки (слои, хром, пункты,
   размеры, движение при удержании, акценты – регламент, раздел 13), таблица по 0,5 с,
   субтитры по группам без одиноких коротких слов (7.8). Пустых заготовок – мест под будущие
   пункты, серых полос, пустых полей, точек «печатает» – в раскадровке нет (4.9): карточка со
   списком, чатом или терминалом растёт с каждым пунктом и стоит по центру зоны (4.10).
5. **«Да» студента.** Покажи раскадровку целиком. Без «да» ничего не рендерится; любое
   заметное изменение после «да» – новое «да».
6. **Сборка** по `references/layout-patterns.md`: путь А – одна композиция HyperFrames
   (видео спикера, сцены, субтитры, звук), путь Б – планы через ffmpeg и наложение.
   Перед полным рендером – `hyperframes lint` (0 ошибок) и пробный кусок
   (`--start 0 --end 6`) с листом кадров.
7. **Рендер.** `hyperframes render build -o reel.mp4 -q delivery`, затем
   `python3 $S/verify.py reel.mp4` (длительность, размер, частота, громкость).
8. **Приёмка по кадрам** по `references/montage-acceptance.md`:

   ```bash
   python3 $S/frames_sheet.py reel.mp4 --out accept \
     --region split=120,140,840,610 --region visual=60,140,960,1140
   ```

   Затем **техническая проверка** (сборщик или скрипт): `verify.py`, геометрические
   запреты раздела 14 и сверка ролика с раскадровкой (план – `plans.json` из раскадровки):

   ```bash
   python3 $S/frame_check.py frames accept/frames --plans plans.json
   python3 $S/frame_check.py text build/index.html --words-out accept/screen-words.txt
   ```

   **Визуальную приёмку делает свежий приёмщик.** Отдельный агент со свежим контекстом (не
   тот, кто собирал) получает только `reel.mp4`, кадры, листы, `screen-words.txt`, чек-лист
   с регламентом и транскрипт речи (`words-cut.json`) – без раскадровки, кода сборки и
   объяснений сборщика – сверяет экран с речью (числа, имена, файлы) и выносит вердикт.
   Материалы ролей – `montage-acceptance.md`, «Кто принимает». Самоприёмка сборщика не
   считается; сборщик может пройти чек-лист сам до передачи, чтобы не тратить круг.

   Кадр каждые 0,5 с (0,25 с в первые 5 с и последние 6 с) – в `accept/frames/`,
   контактные листы с метками времени и линиями зон – `accept/sheet-*.png`, доля
   изменений по областям – `accept/changes.tsv`. **Открой каждый лист и посмотри**:
   числа не видят текста поверх текста, лица под субтитром, мелкого шрифта, заготовок.
   Отдельно открой кадр 0,00 в полный размер (заголовок-хук читается, вставка заполнена) и
   кадры сплита до и после каждой смены плана (верх волос ≥ y 1000, рот и подбородок ≤ y 1520).
   Заполни таблицу приёмки и проход «текст поверх».
9. **Исправить и повторить.** Любой «провал» – исправить причину в сборке,
   перерендерить и принять заново целиком. Порог не ослабляется.
10. **Передача.** Только с чистой таблицей свежего приёмщика: `reel.mp4`, его вердикт
    дословно, таблица, список прохода «текст поверх», листы хука и финала, последний
    кадр, что изменилось против раскадровки. Дальше – шаг 4, публикация.

## Шаг 4. Публикация

Готовый файл – `reel-captioned.mp4` (этап 1) или `reel.mp4` (этап 2), только после чистой
приёмки. В скилле нет API публикации и нет скрипта, который публикует: выкладка идёт только
через интерфейс приложения – руками человека или, по его явному слову, кликами агента (п. 2).

1. **По умолчанию – человек выкладывает сам.** Перенесите mp4 на телефон и загрузите как
   рилс в приложении Instagram обычным способом (или импортируйте в приложение Edits и
   выложите оттуда). Обложку, подпись, хэштеги и время публикации выбирает человек.
2. **По желанию – агент кликами в Edits на macOS.** Агент импортирует готовый файл в
   приложение Edits на Mac и нажимает «Поделиться» настоящими кликами мыши через скилл
   управления экраном. Работает только на macOS, где Edits установлен и в нём выполнен вход
   в нужный аккаунт, и только если у агента есть скилл управления экраном – не у всех.
   Пункты меню зависят от версии приложения: агент смотрит на экран, а не кликает по
   памяти.
   Как это сделать по шагам – скилл `../reels-edits-publish/SKILL.md`.
3. **Нельзя:** публиковать без явного слова человека для этого конкретного файла («да,
   публикуй reel.mp4»); публиковать пробный или тестовый файл; публиковать «на всякий
   случай» или по догадке; использовать API публикации и сторонние сервисы
   автопостинга. Слово на один файл не распространяется на следующий.

## Правила монтажа

Коротко (подробно, с обоснованием – `references/montage-rules.md`):

- Режем только по тишине, никогда по слову. Край реза проверен по звуку, а не только по
  времени слова от распознавателя.
- Скрипт не вырезает смысл сам. Повторы и оговорки – предложение агента, решение студента.
- Порядок: транскрипт исходника, вырезание, проверка, ускорение последним.
- Пауза сжимается до 0,25 с, а не до нуля: речь без воздуха звучит рвано.
- Фейд на стыке несколько миллисекунд, иначе слышен щелчок.
- Громкость около -14 LUFS, пик не выше -1 dBTP (проверка допускает небольшой запас).
- 1080x1920, 30 fps сразу: смена частоты кадров после монтажа сдвигает длину.
- Субтитры и важное – внутри безопасной зоны: центр субтитра на 0,78 высоты, ничто не ниже 0,82, не уже полей; кадр с субтитром смотрят глазами.
- Провал проверки не обходят флагами: показывают студенту и исправляют причину.

## Известные ограничения

- **Один говорящий.** Несколько голосов, диалог, музыка поверх речи – не поддерживаются
  (в шумной сцене проверка тишины мешает: `--no-energy`).
- **Вертикальный исходник.** Горизонтальный вписывается с чёрными полями, без кадрирования
  и слежения за лицом.
- **Нет b-roll и чужих клипов.** Этап 1 – склейка кусков одного дубля; этап 2 добавляет
  только графику (UI-макеты из слов речи) и файлы, которые дал студент.
- **Этап 2 проверен на одном живом дубле.** Кроме синтетического пробного ролика (19 с)
  по регламенту собран и принят по кадрам ролик из настоящего дубля (около 46 с, крупный
  план, один спикер, путь А). Дубли со спикером на средней дистанции, с руками у лица,
  с микрофоном в кадре и путь Б на живом дубле не проверялись. Шрифтов широкого «техно»
  гротеска в той проверке не было – субтитры шли жирным нейтральным гротеском.
- **Метки времени на листах приёмки** рисует Pillow или фильтр `drawtext`; без обоих листы
  без меток, время берётся из `accept/index.txt`. Путь с `drawtext` проверен только тестом
  на собранную команду.
- **Повторы ищутся по тексту и только между фразами.** Заикание внутри фразы («и и»)
  и оговорка в середине фразы не режутся: слова внутри фразы не вырезаются по одному.
- **Распознавание идёт одним куском на весь дубль.** Whisper при длинной записи может
  «проглотить» дословный повтор, и в `words.json` его не будет: в таблице он не
  появится, а в готовом видео останется. Если студент знает, что повторял фразу, а в
  таблице её дубля нет, скажи ему об этом и предложи вырезать по времени (план можно
  поправить вручную, см. `references/formats.md`) или переснять.
- **Таймкоды слов приблизительные.** Поэтому резы подстраиваются под тишину по звуку, а
  кадры стыков нужно смотреть глазами.
- **Движок `groq`: один запрос в Groq на весь звук, без нарезки на куски.** Лимит размера
  файла зависит от аккаунта: см. `--max-upload-mb`. У движка `local` лимита нет, но на
  процессоре он заметно медленнее, а первый запуск скачивает модель.
- **Локальный движок проверен только тестами с подменённой моделью.** Настоящий
  `faster-whisper` в тестах не запускается и модель не скачивается.
- **Лимит длительности рилса** задаётся параметром `--max-duration`, а не зашит: проверьте
  актуальное значение у Instagram.
- **Субтитры: два способа, у каждого своя цена.** `ass` требует ffmpeg с libass (стандартная
  формула Homebrew его не содержит), `png` требует Pillow. Способ `ass` проверен только
  тестами на файл `.ass` и на сборке без libass: на ffmpeg с libass вшивка не прогонялась.
  Способ `png` вшивает «как нарисовано»: внешний вид повторяет стиль ASS по размерам, но с
  libass пиксель в пиксель не сравнивался. В `ass` ширина строки оценивается, а не измеряется
  шрифтом; в `png` она измеряется шрифтом.
- **Резы по звуку на настоящем дубле не прогонялись.** Охрана речи и разбиение на фразы
  отлажены на словах настоящего дубля, а резы по тишине – на синтетическом звуке с теми же
  таймкодами.
- **Публикации через API нет.** Агент может выложить ролик только кликами в Edits на
  macOS по явному слову человека (шаг 4); по умолчанию выкладывает человек.
