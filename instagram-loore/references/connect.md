# Подключение Loore

Источник: https://docs.loore.ai/authentication и https://docs.loore.ai/clients/cli

## 1. Ключ

1. Зарегистрируйтесь на https://loore.ai/register.
2. Кабинет https://app.loore.ai → **Настройки → API и MCP** → создать ключ.
3. Ключ показывается **один раз**. Сохраните сразу в хранилище секретов. Потеряли – выпустите
   новый, старый отзовите.

Один ключ авторизует и MCP, и REST. Удобно держать отдельный ключ на каждого агента –
отзываются по одному, мгновенно.

Передаётся **только** заголовком `Authorization: Bearer <ключ>`. Ключ в URL или query сервер
не принимает.

Храните в переменной окружения, а не в командах (напечатанное остаётся в истории оболочки):

```bash
# ~/.zshrc или ~/.bashrc; файл не коммитить
export LOORE_API_KEY='<ВАШ_КЛЮЧ>'
```

## 2. Claude Code

```bash
claude mcp add --transport http loore https://mcp.loore.ai/mcp \
  --header 'Authorization: Bearer <ВАШ_КЛЮЧ>'
```

Проверка: команда `/mcp` в сессии.

Вариант для команды – `.mcp.json` в корне проекта (этот файл с ключом не коммитить):

```json
{
  "mcpServers": {
    "loore": {
      "type": "http",
      "url": "https://mcp.loore.ai/mcp",
      "headers": { "Authorization": "Bearer <ВАШ_КЛЮЧ>" }
    }
  }
}
```

## 3. Codex

Codex читает ключ из переменной окружения – флага для заголовка у него нет:

```bash
export LOORE_API_KEY='<ВАШ_КЛЮЧ>'
codex mcp add loore --url https://mcp.loore.ai/mcp --bearer-token-env-var LOORE_API_KEY
```

Проверка: `codex mcp list`.

## 4. Без MCP – REST

Любой инструмент доступен как `POST https://mcp.loore.ai/v1/<метод>` тем же ключом.
Имя MCP-инструмента с `_` превращается в путь с `-`: `ig_analytics` → `/v1/ig-analytics`.
Есть исключения, например: `get_credit_balance` → `/v1/billing-balance`,
`estimate_credit_cost` → `/v1/billing-estimate`. Полное соответствие – https://docs.loore.ai/mcp/tools

Обёртка в скилле:

```bash
bash ~/.claude/skills/instagram-loore/scripts/loore.sh ig-profile '{"username":"@brand"}'
```

Машинный контракт API: https://app.loore.ai/api/openapi.json

## 5. Первый вызов

Попросите агента:

```text
Подключись к Loore, перечисли доступные инструменты и вызови skill_list –
это готовые пайплайны Loore, они выполняются на их стороне через skill_run.
```

## Ответы и отказы

Ответ всегда в одном конверте:

```json
{ "status": "ok", "result": { } }
{ "status": "error", "error": "...", "details": { } }
```

| Код | Значит | Что делать |
|---|---|---|
| `400` | неверные аргументы | исправить аргументы |
| `401` | ключа нет, отозван или испорчен | проверить заголовок: `Bearer`, пробел, значение |
| `402` | кончились кредиты или квота | остановиться, сказать человеку |
| `403` | метод вне прав ключа или тарифа | другой метод может работать |
| `404` | объект не найден | проверить идентификатор |
| `409` | конфликт идемпотентности или задача уже в работе | не повторять с тем же ключом |
| `429` | бюджет запросов исчерпан | подождать, повторить с нарастающей задержкой |
| `500` | ошибка сервера | можно повторить один раз |
| `502` | метод без реализации | не повторять |

У денежных и долгих операций можно передать заголовок `Idempotency-Key` – повтор с тем же
ключом и телом вернёт первый результат, а не запустит работу второй раз.
